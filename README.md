# astra-silent-monitor

Скрытый сервер мониторинга на Astra Linux SE 1.8 (ВМ на VMware ESXi) для
нескольких изолированных сетей. Установка полностью без интернета.

**Принципы**

- Каждая сеть — отдельный vNIC и port group; между сетями нет ни
  маршрутизации, ни мостов, ни общих сервисов.
- Сервер только опрашивает узлы (Zabbix, пассивные агенты, PSK) и ни с
  кем не разговаривает по своей инициативе.
- В наблюдаемых сетях у сервера нет открытых портов; на ping, сканирование
  и ARP-поиск он не отвечает.
- Вход (SSH и веб) — только из отдельной админской сети с заданных адресов.
- Исходящий трафик разрешён только к узлам мониторинга на порт 10050 и ping.
- Все пакеты — из официальных репозиториев Astra (подписаны, работают с ЗПС).

## Состав

| Файл | Где запускать | Что делает |
|---|---|---|
| `1-prepare-online.sh` | Astra той же версии **с интернетом** | Скачивает все пакеты с зависимостями, собирает подписанный локальный репозиторий, скачивает агент для Windows, упаковывает всё в архив |
| `2-install-offline.sh` | Сервер, консоль ESXi | Firewall, ядро, сеть, PostgreSQL, Zabbix, веб, SSH, аудит, ЗПС/МКЦ |
| `3-gen-psk.sh` | Сервер | Ключ на каждый узел, комплекты установки агентов по сетям |
| `4-add-hosts.sh` | Сервер | Добавляет узлы из `hosts.txt` в Zabbix через API |
| `5-verify.sh` | Сервер | Проверяет изоляцию и «невидимость» |
| `windows/install-agent.ps1` | Windows-ПК | Агент в режиме «только опрос», PSK, брандмауэр только на сервер |

## 0. ESXi

1. Для каждой наблюдаемой сети — отдельный port group (лучше отдельный
   vSwitch с отдельным аплинком; если VLAN — свой VLAN ID).
   Плюс отдельный port group для админской сети.
2. В каждом port group: **Security → Promiscuous mode, MAC address changes,
   Forged transmits = Reject**.
3. Сеть управления ESXi (vmk0) — не в одной из этих сетей.
4. ВМ: vNIC типа VMXNET3 на каждую сеть (всего до 10).
5. **Важно:** до окончания установки у vNIC наблюдаемых сетей снимите
   галочку *Connect at power on* — иначе установщик ОС может запросить
   DHCP и «засветить» имя машины.
6. Свой MAC вместо префикса VMware (необязательно): ВМ выключена →
   *Edit settings → Advanced → Configuration parameters*:
   `ethernetN.addressType = "static"`, `ethernetN.address = "02:xx:xx:xx:xx:xx"`,
   `ethernetN.checkMACAddress = "false"`.
7. VM Options → VMware Tools → *Synchronize guest time with host* — если в
   админской сети нет NTP.
8. Диск ВМ — по возможности на зашифрованном хранилище (VM Encryption).

## 1. Установка Astra

- Astra Linux SE 1.8, уровень защищённости **«Усиленный»** (ЗПС + МКЦ).
- Минимальный набор: без графики (или только Fly для консоли), без
  сетевых служб. Сеть в установщике не настраивать.
- Создать пользователя-администратора (по умолчанию `admin` в config.env).

## 2. Подготовка комплекта (машина с интернетом)

На машине с той же версией Astra (можно временная ВМ), с подключёнными
репозиториями main и extended:

```bash
cp config.env.example config.env    # задать AGENT_VERSION и сети
cp hosts.txt.example  hosts.txt     # можно позже, уже на сервере
sudo ./1-prepare-online.sh
```

Результат: `bundle/astra-silent-monitor-bundle.tar.gz` и `.sha256`.
**Запишите SHA256 на бумагу** — сверите на сервере.
Сверьте SHA256 агента Windows с контрольной суммой на zabbix.com.

## 3. Установка на сервере (без интернета)

```bash
sha256sum astra-silent-monitor-bundle.tar.gz   # сверить с бумагой
tar xzf astra-silent-monitor-bundle.tar.gz && cd astra-silent-monitor
ip -br link                                    # сверить имена интерфейсов и MAC с ESXi
nano config.env && nano hosts.txt
sudo ./2-install-offline.sh                    # из консоли ESXi
```

После этого подключите vNIC наблюдаемых сетей в ESXi (*Connected*).
Если включались ЗПС/МКЦ — `reboot`.

Отдельный шаг можно повторить: `sudo ./2-install-offline.sh firewall`
(после изменения hosts.txt — шаги `firewall network`).

## 4. Агенты на ПК

```bash
sudo ./3-gen-psk.sh      # ключи + psk-export/<сеть>/
sudo ./4-add-hosts.sh    # узлы в Zabbix
```

- **Windows:** скопировать `psk-export/<сеть>/` на флешку, на ПК запустить
  `install-<имя>.cmd` от администратора. Скрипт удалит свой ключ с флешки.
- **Linux (Astra 1.8):** `sudo ./install-<имя>.sh`.
- **На каждую сеть — своя флешка.** Перенос одного носителя между
  изолированными сетями — самый частый путь утечки.
- После установки: `rm -rf psk-export` на сервере, флешки очистить.

## 5. Проверка

```bash
sudo ./5-verify.sh
```

Снаружи, с ПК в наблюдаемой сети, которого **нет** в hosts.txt:
`nmap -sn <IP>`, `nmap -Pn -p- <IP>`, `arp-scan -l` — сервер не должен
обнаруживаться.

## Что важно помнить

- Полной невидимости не бывает: тот, кто снимает трафик в сегменте или
  смотрит журнал соединений на ПК, увидит обращения сервера. Схема защищает
  от сканирования, обнаружения и подключения к серверу.
- Сервер — единственная точка, где сети соприкасаются. Никаких лишних
  программ, только обновления из официальных бюллетеней Astra (через тот же
  способ: новый комплект с машины с интернетом).
- Оповещения — только внутри админской сети (`ADMIN_SMTP`), никаких
  Telegram и внешней почты.
- `config.env`, `hosts.txt`, ключи и `psk-export/` в git не коммитятся
  (см. `.gitignore`). Репозиторий — только приватный.

## Готовый комплект без машины с интернетом

Комплект собирается автоматически в GitHub Actions (официальный контейнер
Astra Linux 1.8) и выкладывается в раздел **Releases** этого репозитория.

- Скачайте `astra-silent-monitor-bundle.tar.gz`, `.sha256` и `BUILD-INFO.txt`.
- В `BUILD-INFO.txt` указана версия Astra, для которой собран комплект. Она
  должна совпадать с версией на сервере (`cat /etc/astra_version`).
- Нужна другая версия: *Actions → Сборка офлайн-комплекта → Run workflow*,
  указать версию, например `1.8.4`.
